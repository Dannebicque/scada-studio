# Contribution

## Workflow
1. Ouvrir une issue avec le contexte, la valeur utilisateur, les critères d'acceptation et les dépendances.
2. Créer une branche `feat/<issue>-description` ou `fix/<issue>-description`.
3. Ouvrir une PR liée à l'issue ; fournir captures ou démonstration pour l'UI.
4. Exécuter lint, tests unitaires, tests de contrat et vérifications de sécurité pertinentes.
5. Documenter tout changement de schéma ou de contrat d'extension.

## Definition of Done
- Critères d'acceptation vérifiés.
- Tests pertinents ajoutés, CI verte.
- Erreurs, états de chargement et déconnexion traités.
- Accessibilité clavier et sémantique contrôlées pour l'UI.
- Documentation et migrations à jour.
- Aucun secret dans les commits, journaux ou exports.

## Priorités
`P0` bloque la fondation ou la sécurité ; `P1` est nécessaire au MVP ; `P2` est une amélioration différable.
